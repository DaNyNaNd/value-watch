# Contributing

Thanks for taking the time to contribute.

This project is intentionally small. The best contributions make it clearer, easier to use, and more practical without expanding the framework.

## Before You Open A Pull Request

- Open an issue or start a discussion before making major changes.
- Prefer small, focused pull requests.
- Keep the existing planning framework intact.
- Choose simplicity over completeness.
- Do not add new planning documents without strong justification.

## Philosophy

This project optimizes for:

- shipping
- simplicity
- decision making
- avoiding scope creep

It does not aim to be exhaustive documentation.

## Commit Message Format

This project uses [Conventional Commits](https://www.conventionalcommits.org/).

- `feat:` for user-visible additions to the starter kit
- `fix:` for corrections
- `docs:` for documentation-only improvements
- `chore:` for maintenance
- `refactor:` for restructuring without changing the framework
- `feat!:` or `BREAKING CHANGE:` for incompatible template changes

Examples:

- `feat: add pull request template`
- `fix: correct broken README link`
- `docs: clarify MVP Contract wording`
- `chore: normalize markdown formatting`

Release notes and `CHANGELOG.md` entries are generated from these commit messages.

## What Makes A Good Contribution

- Clarifies existing guidance
- Improves navigation or readability
- Fixes confusing wording
- Preserves the lightweight nature of the kit
